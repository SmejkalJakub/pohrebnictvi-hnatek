# Master prompts: new content types and three new funeral-home templates

**Status:** draft 2, 2026-11-10 (adds Czech law, the new content types and speed requirements). Written for Jakub Smejkal's team.

**Background for every prompt:** [docs/research/funeral-ux.md](../research/funeral-ux.md), especially §4a (Czech law), §4b (trends and speed), §7 (ban list) and §8 (new content types).

**Flow:**

```
Prompt 0  Claude Code  ── new content types in core (schemas, gate, CMS, fixture) ──┐
                                                                                      ├─► Prompt 2  Claude Code
Prompt 1  Claude Design ── three directions → review → full comps ───────────────────┘   (one run per template)
```

- Prompts 0 and 1 can run at the same time. Prompt 1 designs the new content with placeholder data; Prompt 0 makes that data real.
- Prompt 2 runs after both, once per approved direction, one template at a time.
- **Lawyer check:** the ⚖ rules in research §4a should be confirmed before any template with death notices goes live, but this does not block design or build.

**What to attach to Claude Design** (it cannot read this repository):

1. `docs/research/funeral-ux.md`
2. Screenshots of the two existing templates at 375 px and 1280 px, from `docs/qa/screens/rodinna-tradice/` and `docs/qa/screens/dustojna-jednoduchost/`. `home`, `jak-postupovat`, `cenik` and `kontakt` are enough, including the `-grey` variants. They are regenerated by `npm run qa`, so rerun it if they predate a template change.
3. The Hnátek logo pack preview `clients/hnatek/brand/preview/brand-overview.png`, so it sees a real client logo the palettes must sit next to.

## Prompt 0: Claude Code (new content types in core)

Run first, at the repository root, in its own session.

```text
Extend the content model of this Astro template system with the new content types decided in
docs/research/funeral-ux.md §8, so that new and existing templates can render them. You work in core,
tools, fixtures and docs, never in templates/ beyond what the build needs to keep passing.

READ FIRST
- docs/research/funeral-ux.md §4a (Czech law; rules L1–L14) and §8 (the new types and their fields)
- docs/content-contract.md (all), docs/editable-fields.md, docs/template-contract.md §3–§6 and §9
- core/content/schemas.ts, core/content/collections.ts, core/content/load.ts, core/content/view-models.ts,
  core/gate/rules.ts, core/gate/launch-check.ts, tools/cms/pages-config.ts, tools/cms/generate.ts,
  fixtures/neutral/, tools/client/new.ts

SCOPE (each type optional; nothing changes for a site that does not switch it on)
1. notices (Smuteční oznámení / obřady): collection + routes contract /oznameni/ and /oznameni/<slug>/.
   Fields per research §8, including publishFrom/publishUntil, noindex, livestreamUrl (https, link
   only), parte image or PDF, ceremony {date, time, placeName, address?, mapUrl?, type}, familyNote,
   consent {orderedBy, date, basis: "objednavka" | "souhlas"}.
   Gate rules (new ids in the G-07x range, Czech messages like the existing ones):
   - a published notice without a consent record is an error in every mode;
   - expired notices (publishUntil < build date) are not built;
   - no price, service or promotional fields exist on a notice (by schema), and the view model for
     notice pages exposes nothing promotional (research L1).
   Notices never appear in sitemap.xml when noindex is true; SeoHead gets robots noindex for them.
   A QR code (SVG, generated at build, no runtime service, no new network access) per notice URL.
2. Pages: add optional page ids pro-ucastniky, pohreb-predem, pravni-informace (to PAGE_IDS; not
   required pages), with nav handling like ochrana-osobnich-udaju.
3. people: collection (name, role, photo?, phone?, order, published) + approvals.json consent entry
   per person; gate: a published person without recorded consent is a production error.
4. faq: collection (question, answer Markdown, topic, order, published).
5. documents: collection (title, file PDF in src/assets/documents/, kind: rad-pohrebni-sluzby |
   obchodni-podminky | reklamacni-rad | other, validFrom). Files are copied to dist as-is.
6. legal info singleton (adr: {name default "Česká obchodní inspekce", url default
   "https://adr.coi.cz"}, complaintsContact?) and a view-model helper for a footer link (research L10).
7. pricing: per-group includes[] / excludes[]; make vatNote rendering mandatory where prices show
   (research L9) — add a gate rule only if you can express it without template knowledge, otherwise
   document it as a template invariant in template-contract §6.
8. Manifest: new supports flags (notices, people, faq, documents, guestInfo, prePlanning) and
   site.config features switches; G-005 must reject a feature the template does not support.
   Set every new flag to false for rodinna-tradice and dustojna-jednoduchost, so they keep passing.
9. CMS: .pages.yml generation for every new type, Czech labels and help texts, media folder for
   documents; notices get a clear "Souhlas objednatele" group.
10. Fixture: realistic Czech PLACEHOLDER data for every type in fixtures/neutral (marked placeholder,
    obviously fictional names, demo dates relative to "now" handled so builds stay deterministic —
    use a fixed fixture date via an env or config, do not depend on the wall clock in tests).
11. Launch check: new tracked facts where a type displays business facts (people phones, ADR).
12. Docs: content-contract (new §§), editable-fields, template-contract (§3 manifest flags, §4 routes,
    §6 invariants: no promotional content on notice pages; footer link to právní informace when the
    singleton is set; prices with vatNote), client-workflow, and the /site-build and /site-revise
    skills (how to fill and approve the new types).

RULES
- Core stays layout-free (no styles, no default class names; qa/structure.spec.ts checks it).
- Static only: no runtime services, no new network access at build beyond npm install.
- Code style (user rule): braces and a body on its own line for every if/else; no `cond && doThing()`;
  no nested or chained ternaries.
- Do not touch clients/*, exported repos or live sites.

VERIFY
npm test, npm run lint, npm run typecheck, npm run qa (A and B unchanged and green),
npm run client:validate -- hnatek and hnatek-b (still PROTOTYPE: PASS), and an export of the neutral
fixture via tools/export (RESULT: PASS). Report the new gate rules, schema changes and anything you
had to decide that the research left open. Commit nothing until asked.
```

## Prompt 1: Claude Design (visual directions and comps)

```text
You are the design lead for a small studio that builds websites for Czech family funeral homes. We
already ship two templates, and we need THREE more, so that a funeral home can choose between five
templates that are each clearly different, each current, fast, legally sound in Czechia, and each
feeling made by a person.

READ FIRST (attached)
- funeral-ux.md: our research. §1–§4b are requirements (including Czech law in §4a), §6 is the map
  of open design positions, §7 is a ban list, §8 lists the new content types you must design.
- Screenshots of template A "Rodinná tradice" (warm letterhead: centred serif wordmark, dark utility
  strip with the nonstop number, editorial asymmetric hero, prose services, dot-leader price list)
  and template B "Důstojná jednoduchost" (calm public signage: sticky header with emergency button,
  fixed mobile bottom bar with two call buttons, sans throughout, tables, uniform grids).
- A real client logo (dark green + gold). Every palette you propose must sit next to a logo like it
  without clashing, without per-client colours.

WHO THE SITE IS FOR
- Someone whose relative has just died, often at night, often on a phone, often 60+, under stress.
  First question: "Who do I call, and are they there right now?" Then "what happens next?", then
  "what will it cost?". Also: funeral guests looking for a notice and the ceremony time and place;
  people planning ahead; families returning after the funeral (urn, documents).
- Language is Czech. Use real Czech text in comps (see CONTENT), never lorem ipsum. Check diacritics
  in every font: "Příliš žluťoučký kůň úpěl ďábelské ódy" in every weight you use.

CONTENT YOU HAVE TODAY (fixed; design for it)
- company: brandName, legalName, IČO/DIČ/register entry, tradition.publicWording (e.g. "Rodinná firma
  se 40 letou tradicí"), foundedYear (often unknown), familyOwned, logo (optional).
- contact: 1 location (street, city, postal code, map link), several phones (office, office mobile,
  flowers), e-mails. officeHours: weekly groups with breaks + holiday note.
- emergency: the 24/7 transport line ("Nonstop převoz zesnulých"), short note, service area.
  It is separate from office hours and must never share a block or heading with them.
- pages (title, navLabel, lead, optional excerpt, optional heroImage, Markdown body): home,
  jak-postupovat, sluzby, rakve, kvetiny, o-nas, kontakt, cenik, ochrana-osobnich-udaju.
- services (6–10): title, summary, category (ceremony, transport, arrangements, cremation, memorial,
  other), featured, optional image, optional price group link, Markdown body.
- guidance (5–10 steps): title, summary, phase (first-hours, first-days, arrangements, after-funeral),
  situations (any, home, hospital, care-home, abroad), checklist, contact prompt (emergency / office /
  none), Markdown body. The guide opens with "Kde blízký člověk zemřel?"; picking a situation keeps
  only the relevant steps visible. It is done with links + CSS (:target), no JavaScript: design it as
  links/buttons that change what is shown below them.
- coffins (0–20), flowers (0–15): name, code/material or type, summary, optional photo.
- pricing groups: items with label, description, kind (fixed / from / range / on-request), amount,
  unit; prices may be marked "UKÁZKA" (demo) with a demo notice. Design both.
- Homepage sections, ordered per client: hero (first), next-steps, services, family-story,
  catalogue-links, contact-summary (required).

NEW CONTENT YOU MUST ALSO DESIGN (being added to the model now; use the placeholder data below)
- Smuteční oznámení / obřady: a list page "Oznámení a obřady" (upcoming ceremonies first, then recent
  notices) and a notice page: name, "* 3. 4. 1941 † 2. 11. 2026", optional photo or the printed parte
  as an image, ceremony "Rozloučení se koná v pátek 14. 11. 2026 v 10:00 ve smuteční síni ve Vyškově",
  map link, ceremony type, optional "Sledovat přenos obřadu" link (link only, never an embed), a short
  family note, "Kondolence" as an instruction (no comment form), a printable QR code. ALL names
  fictional and marked placeholder.
  LEGAL (Czech law, funeral-ux.md §4a L1): no advertising in connection with informing about a death.
  Notice pages carry NO service teasers, prices, "Objednejte", "Naše služby", banners or promo CTAs.
  Only neutral identification of the publisher and the practical facts. Show how your template keeps
  its nonstop line on these pages in a neutral, non-promotional form, and flag it for legal review.
- Pro účastníky pohřbu: a guest page (finding the hall, parking, dress, ordering flowers, livestream
  etiquette).
- Lidé: the team (name, role, optional photo, optional direct phone). Must look complete without
  photos.
- Ceník: per group "V ceně je zahrnuto" / "Není zahrnuto" lists; prices always final incl. DPH with a
  visible "Ceny jsou uvedeny včetně DPH" note (law §4a L9); a print/A4 version of the price list.
- Dokumenty ke stažení: řád pohřební služby, obchodní podmínky, reklamační řád (PDF list).
- Právní informace: a quiet page + a footer link on every page (ADR: Česká obchodní inspekce,
  adr.coi.cz; complaints contact).
- Časté otázky: grouped questions (e.g. "Kdo může vypravit pohřeb?", "Co když se nikdo do 96 hodin
  nepřihlásí?", "Kdy si mohu vyzvednout urnu?").
- Pohřeb bez obřadu deserves a first-class path (reportedly about half of Czech funerals, most of
  them in Prague; unverified figure).
- The footer always shows legal identification (name, sídlo, IČO, OR zápis) — law §4a L8.
Every new type is optional per client, so every layout must also look complete without it.

NON-NEGOTIABLE RULES
- The nonstop line is visible in the first screen at 375×667 on every page, or in a persistent bar
  that does not cover content. It is a tel: link whose visible text includes the label and number.
- Office hours and the nonstop line never share a container or heading.
- Body text ≥ 18 px; contrast ≥ 4.5:1 text, ≥ 3:1 UI and focus rings; primary tap targets ≥ 44 px;
  works at 320 px and at 200 % zoom; links look like links; no hover-only meaning.
- Fast by construction (funeral-ux.md §4b): static pages, no carousels, sliders, parallax, scroll
  animation, autoplay, modals, cookie banners or third-party embeds; JavaScript only for the mobile
  menu; the hero must work with text alone (so the largest paint is text); at most 2 font families
  and 3 weights; no decorative motion.
- No newsletter sign-up, e-mail capture or "send me offers" anywhere (law §4a L1).
- Fonts: free to self-host (OFL or similar) with Czech (latin-ext). Excluded as too default: Inter,
  Roboto, Arial, Helvetica, Open Sans, Montserrat, Poppins. Taken by A and B: EB Garamond,
  Source Sans 3, Literata, Public Sans, IBM Plex.
- No AI-generated or stock imagery of people. Illustrations only if they can be commissioned or drawn
  by hand later; show them as clearly marked placeholders.

BAN LIST (any of these fails a comp)
gradients of any kind; glassmorphism; glows; soft drop shadows as the main depth device; large uniform
border-radius on everything; pill buttons by default; a coloured stripe on one side of a card or
callout (left/top accent border); rows of three identical cards with an icon on top; nested cards;
a badge or eyebrow pill above the H1; centred hero with two buttons; stat banners ("40+ let",
"1000+ rodin"); decorative 1-2-3 steps; emoji or generic icons standing in for words; testimonial
carousels or review walls; logo walls; doves, wilting flowers, sunsets, candles as decoration, hands
holding hands; indigo/violet accents; everything centre-aligned; every section the same height;
urgency or sales mechanics (countdowns, "limitovaná nabídka", plan upsells, calculators).
Microcopy bans: "Jsme tu pro vás na každém kroku", "Vaše cesta", superlatives, exclamation marks,
euphemisms in UI text ("odešel na věčnost"); use "zemřel", "úmrtí", "pohřeb".

WHAT MUST MAKE EACH TEMPLATE DIFFERENT
Each new template differs from A, B and the other two new ones in STRUCTURE, not colour. Use the
axes in funeral-ux.md §6; change at least four of: homepage entry pattern; emergency CTA pattern;
navigation (desktop and mobile); typography; colour mood; density; imagery approach; separation
device; services IA (one long page vs index + detail); pricing presentation; guidance presentation;
and now also how notices and ceremonies are listed. Greyscale test: at 375 and 1280 px all five
templates stay recognisably different.

STARTING HYPOTHESES (replace any with a better idea; explain why)
C · "Rozcestí" (the fork): the homepage opens with "Co právě potřebujete?" and large answers
    (Někdo právě zemřel / Hledám oznámení nebo obřad / Připravuji pohřeb / Chci se informovat předem),
    the nonstop line set in words directly above. One column, one decision per screen, a legibility-
    first sans (e.g. Atkinson Hyperlegible or Lexend), very sparse.
D · "Parte" (the notice): a restrained modern take on the Czech smuteční oznámení — framed blocks with
    a thin rule, centred only where it carries meaning, a contemporary serif with optical sizes,
    near-black on warm white, one muted accent. The notices section is its natural centre; pricing as
    a printable price sheet; guidance as a calm timeline. Never sombre, religious or ornamental.
E · "Kancelář na náměstí" (the local office): a sign-like horizontal header with the nonstop line
    inside it, a two-column desktop layout with a persistent contact column, a slab or grotesque with
    character, stone/limestone neutrals with one mineral accent; the team ("Lidé") and the premises
    are prominent; guidance as a "Dnes / Tento týden / Později" board that becomes a list on mobile.

DELIVERABLES, PER TEMPLATE
1. Name (Czech, two words) and a 3-sentence concept: who it suits, the one structural idea, why it is
   right for a stressed older visitor.
2. Token sheet: 2 palettes (hex + measured contrast for ink, muted text, accent text, accent button,
   rules/UI lines), 2 font pairings (OFL, latin-ext checked, ≤ 3 weights), type scale, spacing scale,
   the one separation device.
3. Comps with real Czech text: Home at 375 and 1280 (with and without a hero photo); Jak postupovat at
   375 (situation picked / none); Ceník at 1280 (demo prices, included/excluded, DPH note) and its A4
   print version; Kontakt at 375; Oznámení list at 375 and 1280; one notice page at 375 (with and
   without photo, with and without livestream link); Pro účastníky at 375; Lidé at 1280 (with and
   without photos); the footer with legal identification and the "Právní informace" link; header +
   mobile menu open and closed; 404 at 375.
4. The emergency CTA pattern at 375 and 1280, its "high emphasis" variant, and its neutral form on
   notice pages.
5. A filled differentiation table: rows = funeral-ux.md §6 axes + "notices listing", columns = A–E.
6. An honest self-check: ban list, non-negotiable rules, and legal rules L1, L8, L9, L10, L12 (pass/fail).

PROCESS
- First deliver the three concepts as one-page moodboards (type specimen, palette, homepage first
  screen at 375 px, one notice page at 375 px) and STOP for review. Only after approval, produce the
  full comps.
- Do not imitate any existing funeral-home website or brand; do not reuse or recolour A or B.
- If a design idea needs content beyond the lists above, do not fake it: list it as a proposal with
  the field it would need.
```
